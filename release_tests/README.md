# Release tests (independent acceptance)

Жёсткая приёмка перед публикацией. Эти тесты **намеренно** живут вне `pc/tests` и
`android/` и ведутся релиз-линией отдельно от дев-чатов — чтобы приёмку нельзя было
«подогнать» правкой обычных тестов. Гоняются локально перед каждым релизом и в CI.

## Что проверяется

| Файл | Проверяет |
|---|---|
| `test_repo_hygiene.py` | Нет секретов/`.env`/ключей в истории; внутренние доки (`PLAN_*`, `RESEARCH_*`, `ONBOARDING_*`) не отслеживаются; нет тестовых артефактов (`.apkg`, `.log`); есть `README/LICENSE/VERSION/CHANGELOG`; `VERSION` — валидный SemVer. Без импорта кода. |
| `test_release_smoke.py` | Реестр инструментов собирается; ≥30 инструментов; имена валидны и уникальны; у каждого непустое описание; версия парсится. |
| `test_security_invariants.py` | Песочница путей (`resolve_path`) не выпускает за рабочую папку; чёрный список команд покрывает разрушительные операции (`rm -rf`, `format`, `mkfs`, `dd of=/dev/…`, форк-бомба и т.д.). |

## Как запускать

Быстрый прогон (без ключа API — детерминированный):

```bash
python -m pytest release_tests -q
```

Только гигиена репо (мгновенно, без зависимостей приложения):

```bash
python -m pytest release_tests/test_repo_hygiene.py -q
```

Смоук/инварианты импортируют `pc/core`, поэтому нужны зависимости из `pc/requirements.txt`
(`conftest.py` сам добавляет `pc/` в путь).

## Перед релизом — обязательно ещё и «живая» приёмка

Детерминированные тесты не звонят в модель. Перед тегом версии дополнительно прогони
поведенческие evals с реальным ключом (проверяют, что агент реально решает задачи):

```bash
cd pc && python -m evals --live
```

## В CI

- **`hygiene`** — на каждый push/PR (Ubuntu, мгновенно): секреты и утечки внутренних доков.
- **`release-gate`** — на тег `v*` и по ручному запуску (Windows, с зависимостями): весь набор.
