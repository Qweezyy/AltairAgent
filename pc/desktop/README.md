# Нативная оболочка (Tauri v2)

Тонкая нативная обёртка вокруг существующего приложения. **Логика агента не меняется** —
она остаётся на Python. Оболочка:

1. сразу открывает окно с заставкой и поднимает Python-сервер дочерним процессом на порту 8137
   (`main.py --server --parent-pid <pid оболочки>`; занят — любой свободный),
2. ждёт готовности (до ~2 минут, быстрее сдаётся, если бэкенд упал) и переводит окно на его
   локальный адрес; при неудаче — двуязычная страница ошибки с рамкой окна,
3. гасит Python-процесс при закрытии окна; при падении оболочки бэкенд сам завершается по
   `--parent-pid`, чтобы не держать порт.

Весь текущий веб-интерфейс (`static/`) и весь бэкенд (WS `/ws` + REST `/api/*`) работают без
единой правки — окно просто показывает `http://127.0.0.1:<порт>/`.

## Встроенный браузер
`src/browser.rs` размещает вкладки браузера панели как нативные контроллеры WebView2 в
дочерних окнах главного окна (не Tauri-вебвью: страницам не видны глобалы/IPC Tauri, на
рабочем столе и в панели задач браузер не появляется). Отдельный профиль в
`%LOCALAPPDATA%\LocalAIAgent\browser`, порт отладки только на loopback — через него агент
подключается Playwright-ом (`--browser-cdp-port`). Загрузки сохраняются в карантин, дальше их
проверяет бэкенд (`core/browser_downloads.py`).

Каждая своя команда (`set_app_icon`, `browser_*`) должна быть и в `build.rs` (манифест
приложения), и `allow-…` в `capabilities/default.json` — окно открыто на http://127.0.0.1,
а для Tauri это удалённый источник.

## Требования
- Rust (cargo) — оболочка компилируется в нативный бинарь.
- Node + npm — только для Tauri CLI (dev/сборка).
- Windows: WebView2 Runtime (обычно уже установлен; ставится один раз).
- Python-окружение проекта (как для `python main.py`).

## Запуск в разработке
```bash
cd desktop
npm install            # один раз — ставит @tauri-apps/cli
npx tauri dev          # компилирует Rust-оболочку и запускает нативное окно
```
Либо напрямую: `cargo run --manifest-path src-tauri/Cargo.toml`.

В dev-режиме бэкенд запускается интерпретатором из корня репозитория
(`python main.py --server`), путь известен на этапе компиляции (`CARGO_MANIFEST_DIR`).

## Сборка релиза
Отдельно ничего собирать не нужно: `python build_app.py --zip` (из `pc/`) собирает бэкенд
PyInstaller-ом, оболочку `cargo build --release` и кладёт её как `Altair.exe` рядом с
`LocalAIAgent.exe` в `dist/LocalAIAgent/`, затем пакует zip — это и есть релиз.

Оболочка на старте находит `LocalAIAgent.exe` рядом с собой и запускает его без окна
консоли; пользователю не нужен установленный Python.

Установщики Tauri (NSIS/MSI) **выключены** (`bundle.active: false`): они не содержат
Python-бэкенд, и установленное приложение открыло бы пустое окно.

## Почему так, а не переписывать на Rust
Мозг агента (LLM-оркестрация, ~99 инструментов, MCP, память) — это Python, и работа
I/O-bound (ожидание модели по сети). Rust-оболочка даёт нативное окно, WebView2, задел под
автообновление/подпись — не трогая и не замедляя разработку самого агента.
